## 二、四个漏洞与修复（为何改/怎么改/改哪里）

### 漏洞1：HTTP 服务冻结 + watchdog 误杀死循环（最严重，已打到真实流量）
- **现象**：服务日志显示 21:00 连续两次"not responding -> restarted"，且有一条**真实客户端**的查询（"手机本地模型调优"）卡在队列里。
- **根因**：首个语义查询触发冷启动（语料池 5.7s + 嵌入首调 + 裁判进 GPU），检索全程**同步跑在事件循环上** → 整个服务冻结 8-12s → watchdog 3s 探活超时误杀 → 重启丢缓存 → 下一个请求又冷启动 → 循环。**真实用户的第一个查询永远撞在冷启动上**。
- **修复（4 处）**：
  1. `services/mcp_server.py`：`render_tool` 改 `await anyio.to_thread.run_sync(...)`——重活卸工作线程，事件循环保持响应（stdio 行为不变）；
  2. `services/mcp_http_server.py`：新增 `_prewarm()`，uvicorn 启动前把池+嵌入+裁判焐热（起来即热，实测 29s 完成启动）；
  3. `integration/scripts/mcp_watchdog.py`：固定 sleep(4) 自检改轮询 120s（预热期不再误报 still down）；
  4. `retrieval/vector/query.py` 改动五：`judge_candidates` 全程持锁（并发防崩，见漏洞2）。
- **验证**：3 并发查询（含裁判触发）期间 /health **零失败、最慢 464ms**（修复前必然超时）；watchdog 修复后零重启。

### 漏洞2：裁判引擎子进程 jev-score.exe 死循环，无超时无自愈
- **现象**：夜测 02:25 评测卡死 15 分钟；`jev-score` PID 44524 单次判定烧 CPU **2037 秒**、GPU 满载 99%。且**高频复现**（前 25 题触发 2 次，全夜 40+ 次），夜间 GPU 多进程竞争下概率暴涨。
- **影响**：常驻服务下 judge_candidates 的锁永不释放 → 后续所有低置信查询排队瘫痪。
- **修复**：`query.py` 改动五——每次 decide 在单线程池跑，**40s 超时**记 0 分（正常 0.35s），**连续 2 次超时 = 引擎卡死 → close()(含 kill) → 自动重建**，fail-open 继续。
- **验证**：自愈上线后评测不再卡死（全夜 40+ 次自动恢复）；确定性抽样期间又触发多次均自愈。

### 漏洞3：HTTP stateless 模式 call_log 客户端标签全废
- **现象**：M4 对账显示按 night-bombard 查 0 条；实际库里 311 条，但 **309 条 client='unknown'**——"按客户端统计"失效。用户要的"每次真实调用记录"内容在（参数/耗时/成败/召回全文），标签废了。
- **根因**：HTTP stateless 模式 request_context.session 不携带 initialize 的 clientInfo。
- **修复**：`mcp_tools/call_log.py` client_label 加环境变量兜底 `PERSONAL_DATA_MCP_CLIENT_TAG`；`mcp_http_server.py` 启动时置 'http'。
- **验证**：重启后真实调用落库 client='http'（unknown 消失）。stdio 客户端标签不受影响。

### 漏洞4：评测管线自身两处 bug（自伤，已修）
- fragile 分析误用题目对象当结果记录（KeyError，528 题白跑）→ 修正 + **桶级断点续跑**（每桶落盘）；
- flash 生成器空响应不重试（~3% 漏题）、429 限流（6 线程超速）→ 空响应重试 + 4 线程 + 45s 退避（与 full_run 伺候法一致）。

## 四、短板清单（按危害排序）

1. **否定式提问 20%**（辨析桶）——用户说"不是那次"时系统会拿错。真实频率估计低，但一旦发生误导性强。建议：裁判 prompt 支持排除语义，或输出歧义提示。
2. **弱信息查询 ~80%**（合成桶）——"之前我交代的xx事"式提问掉 11pp。这恰是真实使用最高频的问法形态。缓解：MCP 输出附"低分提示"（依赖负样本阈值结论 0.45）；根治靠查询改写（query rewrite）层，今晚未做。
3. **负样本/正常分数分布重叠**——系统不会说"不知道"。0.45 阈值可拦截多数杜撰话题，MCP 输出建议加低置信标注（一行改动，待批）。
4. **裁判引擎死循环缺陷**（jev-score.exe 上游问题）——已用超时自愈兜住，根因在引擎侧（夜间 GPU 竞争下高发）。上游修复需查 D:/Ollama/dl/jev-style-v3 的 jev-score 源码，未动。
