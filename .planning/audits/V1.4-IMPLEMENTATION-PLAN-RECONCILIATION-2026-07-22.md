# v1.4 决策驾驶舱：实现与计划对账

## 结论

v1.4 不是从零开始的前端里程碑。仓库中已经存在 Cockpit、`ui_projection`、API 路由和
定向测试，但它们仍是未提交的 WIP，且安全、证据、真实运行与浏览器 UAT 尚未收口。

因此 Phase 36–40 的定位修正为：

```text
已有实现对账与安全收口
→ authority/evidence 真值补全
→ 既有受控决策流加固
→ 反馈与运行时真实性修复
→ 可审计的真实浏览器 UAT
```

它们不是“重新造一个驾驶舱”，也不能仅凭现有组件测试宣称 v1.4 已完成。

## 审计边界与证据

本次只读取本地工作区；没有修改业务代码、数据库、authority、Serving Snapshot、Watermark、
运行服务、Provider 或任何用户决策记录。

## 关键阻塞与优先级

1. **P0 — 跨源 mutation 面：**先移除 wildcard CORS、实现明确 Origin policy，并用反向测试证明被拒绝时没有调用受控写服务。
2. **P0 — 安全错误与证据链：**错误不能把异常正文送入 UI；状态与决策必须使用 snapshot-bound stable reference 下钻证据。
3. **P0 — 计划/声明真实性：**未提交 WIP、README 的 Phase 40 完成宣称和未执行 UAT 必须被区分，不能提前发布。
4. **P1 — 决策/反馈正确性：**已有写流不回退；在 Phase 38 加上 truth gate、exact preview/replay 负向证明，并修正反馈历史排序/分页。
5. **P1 — 产品验证：**真实浏览器与故障降级 UAT 是 v1.4 的完成条件，不是附加演示。

## 对既有 Phase 36–40 计划的解释修正

| Phase | 原误读 | 对账后的执行含义 |
|---|---|---|
| 36 | 新建 Cockpit 基线 | 审计并收口已有 WIP 的同源安全、safe error、DTO/fixture 与可归档基线。 |
| 37 | 新建状态/External/Decision 页面 | 保留已有页面，补齐 authority/evidence resolver、truthful degraded state 与 Widget 隔离。 |
| 38 | 首次实现决策工作区 | 加固现有受控决策流：资格门、exact preview、confirm/replay、typed recovery 和跨源防护。 |
| 39 | 新建反馈/主动/系统页 | 修复已有分页/排序与健康语义，证明只读和非因果表达。 |
| 40 | 仅追加硬化 | 进行此前未发生的真实浏览器、故障、隐私、可访问性和发布/恢复验收。 |

### Phase 37 / 38 的边界

已有的 guarded decision workflow 不会在 Phase 37 被人为关闭。Phase 37 只增加读取与证据
语义，不能新增写入能力或改变现有 guard policy；Phase 38 专门对现有入口实施服务端真值门、
preview/confirm/replay 和 fail-closed 加固。这既避免计划导致产品倒退，也保持“真值不足不得
启动写入”的最终安全要求。
