<objective>
提供 P0 主题目录、显式反向链接和薄只读 transport，使未来页面可以浏览已存在的高价值主题，但不创建 UI、持久化材料或第二个决定/确认流程。

计划为 v1.5 inactive 预规划；真正执行前必须重审 v1.4 的 CORS/origin/session security 结论，且任何未解决的 cross-origin mutation 风险都会阻止此项进入执行。
</objective>

<threat_model>
- 未加界限的目录/backlink 会暴露过多个人 metadata 或造成浏览器资源耗尽；所有列表必须有固定上限、稳定排序和 cursor/limit 验证。
- 将“相关”用 embedding/共现/LLM 推测表达会被用户误读成事实关系；P0 关系必须由 explicit join 和 fixed vocabulary 产生。
- 新 GET route 不能绕开 v1.4 的 origin/CORS/response sealing；否则只读 surface 会成为未来 write-flow 的安全回归入口。
- 传输层错误不得输出 `str(exc)`、路径、SQL 或 HTML fallback。
</threat_model>

  <action>
实现 `topic.list` 与 `topic.backlinks`，复用 Plan 02 的 exact resolvers 和 authority state。两种 operation 都必须使用 `personal_wiki_projection_v1` 的同一顶层 envelope：`snapshot_bindings`、authority status、freshness、partial、limitations、bounded source/evidence references 与 canonical `projection_checksum` 缺一不可；不得把目录/反链做成缺少真值元数据的轻量特例。Directory 仅从 P0 Project/Goal/Decision 的显式 canonical fields 收集 key，去重后按稳定 canonical sort 返回；使用受限 limit/cursor，列出 type、canonical key、title/template metadata、freshness/authority availability 和 snapshot binding，不在此阶段从 KU/vector/LLM 自动生成主题。
