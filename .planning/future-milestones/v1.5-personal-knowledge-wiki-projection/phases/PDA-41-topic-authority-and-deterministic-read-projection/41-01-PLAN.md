<objective>
建立 Wiki P0 的身份与错误词表基础：只接受可解释的 Project、Goal、Decision TopicKey，为随后只读投影提供稳定的 schema 基元。

这是 v1.5 的预规划任务。实际执行前必须在 v1.4 完成、独立审计通过并重新核对接口后重新验证；本计划本身不授权代码、数据库、Provider、索引或运行时变更。
</objective>

<threat_model>
- 以显示标题、向量近似或模型猜测替代身份，会把不同个人主题误合并；因此身份只能由严格 canonical key 产生。
- 把 `str(exc)`、SQLite 错误或本机路径带入浏览器会泄露运行信息；因此输入/解析失败只能返回有限安全 reason code。
- 复用 `decision_cockpit_projection_v1` 会使 Cockpit 与 Wiki 的消费者无法区分其语义和生命周期；因此 Wiki schema 必须独立版本化。
- 该阶段不得因“解析”而读取或改写任一 Authority；解析层保持纯函数、无 Provider、无索引和无持久化副作用。
</threat_model>

<tasks>
<task type="execute">
  <name>Task 1: 定义严格的 P0 TopicKey 与安全错误契约</name>
  <files>src/personal_knowledge/services/topic_projection.py</files>
  <action>
新增与 `CockpitProjectionService` 相邻但独立的 Wiki read-contract 模块。定义 `personal_wiki_projection_v1`、仅允许的操作（`topic.list`、`topic.get`、`topic.backlinks`）、不可变 `TopicKey` 与 typed safe-recovery/error 结构。

只接受以下 canonical grammar：`project:{scope}`、`goal:{domain}:{scope}:{predicate}`、`decision:{recommendation_id}`。在单一 parser 中一次 URL decode、拒绝空段/未知 type/多余段/不规范编码/无法可逆的分隔符；输出 canonical key，不允许 loader 再做 `split(':')` 或 fuzzy fallback。为后续 transport 预留稳定 code，例如 `invalid_topic_key`、`unsupported_topic_type`、`topic_not_found`、`authority_unavailable`、`authority_binding_missing`、`snapshot_mismatch`、`evidence_unavailable`、`privacy_sealed`、`projection_partial`。

本计划不得实现 Authority 查询、HTTP 路由、页面持久化、LLM、用户编辑器、Chroma/KU 写入或 `docs/wiki/` 改动。
  </action>
  <verify>
运行 parser 的最小单元测试；检查模块只包含纯结构与安全错误基元，不导入 Provider、写服务、Chroma 客户端或 schema migration。
  </verify>
  <done>三种 P0 key 均可解析成 canonical identity；所有拒绝情形都具稳定 code 且不会暴露异常 detail。</done>
</task>
