<objective>
实现受限的 Wiki-first 读取路由：用 fresh Wiki 给高价值 P0 topic 提供快速持久化上下文；在任何不够新、不完整或不存在时，显式回落到结构化 Authority、Active KU/search 和原始证据，而不把 Wiki 反灌为检索/事实输入。

这是 v1.5 的计划，不是执行授权。必须在 v1.4 完成、Phase 41–42 真正实现并通过检查后重新确认实际接口与产品范围。
</objective>

<threat_model>
- 如果 Wiki text 被喂回 KU/Chroma 或 Evidence Authority，派生摘要会被误当作独立证据并形成自证闭环；因此 router 只读取 Wiki manifest/reference，不传递 page body 至任何 writer。
- 如果 partial/stale Wiki 仍优先回答，用户会看到过期结论；因此 required answer section 不满足 fresh 时必须跳过 Wiki 并标识 fallback provenance。
- 如果所有问题强制经 Wiki，会把 long-tail search、冲突查询和未建页主题错误地缩减到目录；因此未能 canonical-resolve 到 P0 TopicKey 的请求直接 bypass Wiki。
- 如果 UI 将 TanStack cache time 解释为 authority freshness，会掩盖 server binding mismatch；因此 UI 只能显示 service verdict，浏览器 invalidation 仅是表现层缓存管理。
- 如果 fallback 从 KU/search 直接提升为 Fact，检索片段会改变事实层级；因此每层结果保留自己的 source kind、snapshot/evidence refs 和 epistemic label。
</threat_model>

    - non-P0/long-tail request 不访问 derived-store，也不触发 materialize/rebuild。
    - router 没有 import/调用 KU writer、Chroma writer、Evidence Authority write、Provider、external action 或 lifecycle mutation。
  </acceptance_criteria>
