<objective>
将 immutable materialization 接入 Wiki read projection：每次 topic read 都由服务端验证 binding，向 UI 和调用者诚实返回 fresh/stale/partial/unavailable/missing，而不是相信旧缓存或启动隐式后台刷新。

这是 v1.5 预规划的未来执行计划。执行前必须等待 v1.4 完成并重新进行 security/interface review；它不授权任何此时的代码、数据库、服务或运行时修改。
</objective>

<threat_model>
- 若浏览器或 latest pointer 自行判定 freshness，旧页面会在上游变更后被伪装为 current；因此 request-time validation 只能在 server authority boundary 发生。
- 若 API 把完整异常、file path 或 datasource detail 放进 limitation，会泄露本机与个人系统结构；因此 response 只返回 reason-code allowlist、typed authority status 与受控 metadata。
- 若 stale read 默默触发 background rebuild，可能绕过审计、消耗 Provider/网络或造成 race；因此 P0 不起 daemon，rebuild 仅为显式、local、受控的 deterministic operation。
- 若 topic read route 错误接入 Cockpit 的 `prepare/confirm` 或既有 write route，会把知识浏览升级为跨域写入口；因此 topic endpoints 保持 GET/read-only，不带 mutation capability。
</threat_model>

扩展 Phase 41 的 `topic.list`、`topic.get`、`topic.backlinks` 服务路径：对 latest derived version 调用 server-side `validate_latest`，比较 captured serving/personal/external/decision bindings 与当前 explicit dependency fingerprints。将 result 包进独立 `personal_wiki_projection_v1` envelope，其中包含 `operation`、`snapshot_bindings`、`freshness.status`、有限 `reason_codes`、`authorities`、`partial`、`limitations` 和 `data`。

行为固定为：全依赖匹配才返回 fresh Wiki projection；essential input mismatch/缺失返回 stale 或 unavailable；non-essential section failure 返回 partial 并移除该 section 的 current assertion；无 derived record 返回 missing。stale version 可以只作为 derived diagnostic/history metadata 返回，绝不可放在 `data.current_summary`、`facts.current` 或其它 current 状态字段。`topic.list` 仅报告逐 topic 的 server verdict，不通过页面生成时间或前端 cache 推断。

如果需要 explicit rebuild，定义一个仅本地/受控 service entry point，输入 canonical TopicKey，输出新 immutable projection version；不得在 `topic.get`、`topic.list`、`topic.backlinks`、page load 或 browser retry 内自动执行 rebuild，也不得调用 Provider、网络或任何 write authority。
  </action>
  <acceptance_criteria>
    - 每个 `topic.*` response 都有 `personal_wiki_projection_v1`、operation、freshness status/reason code、snapshot bindings 与 `partial`/limitations 字段。
    - 一处 captured dependency mismatch 使相应 read 返回 `stale`/`unavailable`，旧 summary 不再位于任何 current field。
    - 无关 topic 保持 fresh；`topic.list` 的多个条目不会共享一个全局 stale flag。
    - `topic.get` 不调用 materialize/rebuild、Provider、network、KU/Chroma/evidence writer 或 personal/external/decision mutation。
  </acceptance_criteria>
  <verify>

  </verify>
  <done>Wiki response 的 freshness 是一次 server-side evidence-backed verdict，而非缓存时间或前端猜测；旧数据不会以 current 形式泄露。</done>
