<objective>
为 Personal Knowledge Wiki 建立独立且可丢弃的物化投影元数据层：保存 immutable page version 与显式依赖 manifest，以确定性 checksum 支持精确失效和无副作用重建。

这是 v1.5 的预规划任务。只有 v1.4 完成、重新核对实际 Authority 接口和安全审计后才可执行；本文件不授权代码、迁移、服务、Provider、向量索引或运行时变更。
</objective>

<threat_model>
- 如果 Wiki store 复制事实正文或 evidence body，它会成为第二个 SSOT；因此 derived-store 仅存标识符、binding、checksum、状态与失效审计元数据。
- 如果用全局 TTL 或每次全表清空判断 freshness，会掩盖依赖图错误并造成无关页面失效；因此只认可显式 dependency row 的精确匹配。
- 如果 checksum 包含 `generated_at` 或未排序字典，等价重建会产生伪差异；因此使用现有 canonical JSON/hash 语义并排除易变时间字段。
- 如果 materializer 直接写 canonical KU、Active Chroma 或 evidence authority，会形成 Wiki 自我检索/自我证据闭环；因此 upstream adapter 一律只读，唯一可写目标是 dedicated derived-store。
- 如果测试读取真实个人库，计划验证会污染或暴露个人数据；因此所有可写验证使用 disposable fixture databases、synthetic IDs 和密封内容。
</threat_model>

创建专用 derived-only store（目标路径由后续运行配置提供，例如 `var/db/personal_wiki_projection.sqlite`），不要向 canonical、serving、external、decision 或 Chroma schema 添加字段。定义 immutable `wiki_projection_versions`、`wiki_projection_dependencies` 与可选 `wiki_projection_invalidations` 记录；version row 仅含 `topic_id`、`topic_type`、`projection_format_version`、`projection_version`、`projection_checksum`、`generated_at`、`freshness_status`、`reason_codes`、source snapshot bindings 与 dependency-manifest checksum。dependency row 仅含 authority、stable ref、expected version/checksum/sequence、essential 标记与 canonical order key。

提供 `connect_rw`（只用于该 derived-store 的原子写事务）以及 `connect_ro`（URI `mode=ro`、`PRAGMA query_only=ON`、foreign keys enabled）的明确接口。一次 materialization 必须在单一事务内插入 version 和完整的 sorted dependency rows；不得 update/overwrite 已存在 version。latest pointer 如有，只是 derived navigation metadata，不能重写历史 version 或代表上游事实。所有 API 参数必须是 canonical TopicKey/依赖对象，拒绝 free-form SQL、文件路径和 page text。
  </action>
  <acceptance_criteria>

    - immutable insert 尝试覆盖相同 `(topic_id, projection_version)` 时失败 closed；latest lookup 可以只读获得 version/manifest。
    - `connect_ro` 执行任何 INSERT/UPDATE/DELETE 失败，且 `connect_rw` 仅接受 derived-store path。
  </acceptance_criteria>

  </verify>
  <done>Wiki persistence 仅保存可以从上游重建的元数据；删除该 store 不会删除、替换或修改任何事实 Authority。</done>

  <action>
建立 `WikiMaterializer` 与纯函数 stale classifier。复用既有 canonical JSON/checksum 约定，对依赖按 `(authority, stable_ref, expected_version_or_checksum, order_key)` 排序；projection checksum 只覆盖 `topic_id`、projection format version、snapshot bindings、canonical dependency manifest 和结构化 section references，明确排除 `generated_at`、render time、浏览器状态与错误文本。

实现只读 Authority fingerprint adapters：Serving 使用 `ServingSnapshotResolver` 的 active snapshot/manifest binding；Personal 使用已验证的 Personal State run/snapshot binding；External 使用 immutable external snapshot/lifecycle heads；Decision 使用 recommendation/event sequence/checksum。每个 adapter 返回受限 `fingerprint` 或 typed status，绝不返回写 service、Provider 或原始正文。classifier 至少输出 `fresh`、`stale`、`partial`、`unavailable`、`missing` 与受限 reason codes：`serving_snapshot_changed`、`personal_snapshot_changed`、`external_snapshot_changed`、`decision_sequence_changed`、`dependency_missing`、`dependency_lifecycle_changed`、`dependency_checksum_mismatch`、`authority_unavailable`、`projection_record_missing`。

实现 deterministic `materialize`/`rebuild`：从 Phase 41/42 accepted resolver 获取 P0 Project/Goal/Decision 的结构化 source references，再建立 manifest 并原子写入 derived-store。它不得调用 Provider、网络、外部动作、promotion、lifecycle mutation、KU extractor、Chroma client 或 Evidence Authority writer。若 required authority 缺失，返回 typed unavailable；非 essential section 缺失时返回 partial + section/reason，而不是虚构叙述。支持唯一受控的 local/manual `materialize` / `rebuild` entry point：它必须显式接收已验证的 canonical TopicKey、以同一 no-provider/no-upstream-write contract 生成首个 P0 version 或后续 rebuild，并输出 derived version/manifest receipt。GET/OPTIONS、Cockpit 页面加载、read router、cursor/retry 与任何 authority-change detector 都不得隐式触发首次 materialize 或 rebuild；缺 page 的读请求只能返回 missing 后走 Phase 43 fallback。不得启动 background worker 或自动 regeneration daemon。
  </action>
  <acceptance_criteria>
    - 相同 synthetic input 的两次 rebuild 生成相同 dependency-manifest checksum 与 projection checksum，即使 `generated_at` 不同。
    - 修改某一 `goal:*` explicit dependency 的 lifecycle head 或 checksum 只使引用它的 topic 状态变为 stale/partial；不相关 Project/Decision 保持 fresh。
    - required Personal/Decision authority 不可验证时，当前 summary 返回 `unavailable` 而非旧内容冒充 fresh；仅 non-essential External section 不可用时可以返回 `partial` 并列出 section limitation。
    - materialization/rebuild 的 call trace 中 Provider/network/external-action/Active Pointer/canonical KU/Chroma/evidence-writer 写入数均为 0。
    - 首次 materialize 仅能由受控 local/manual entry point 在 disposable fixture 或单独授权运行中执行；普通 GET、read router 或浏览器加载的 materialize/rebuild 调用数为 0。
  </acceptance_criteria>

  </verify>
