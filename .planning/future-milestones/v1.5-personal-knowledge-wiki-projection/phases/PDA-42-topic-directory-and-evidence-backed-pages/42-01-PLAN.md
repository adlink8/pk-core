<objective>
在已验证的 Phase 41 只读主题契约之上，建立 Personal Knowledge Wiki 的目录、严格的
客户端 read contract 和 P0 typed routing。该计划只让用户浏览 Project、Goal、Decision
主题；不把 Wiki 变成第二个搜索、事实库或 Decision Workspace。
</objective>

<threat_model>
- T-42-01：使用 display title、subject、predicate 或 evidence 内容拼接 URL，导致个人内容泄露或 Topic identity 漂移。缓解：仅使用 Phase 41 server-issued opaque `topic_id`，并验证 `topic_type` 与页面类型匹配。
- T-42-02：通用 Cockpit envelope 接受错误 operation/旧版本内容，浏览器把别的 authority response 当作 Wiki 主题事实。缓解：每个 Wiki endpoint 使用 literal `schema_version=personal_wiki_projection_v1` 和 literal operation 的 Zod schema。
- T-42-03：authority unavailable 被渲染成“没有主题/没有关联”，造成虚假的零结论。缓解：directory fixture 与页面区分 empty、partial、unavailable、invalid/type mismatch；任何 non-fresh result 保留 server limitations/freshness。
- T-42-04：目录为方便检索而调用 semantic search、POST 或 authority merge，形成新的可写/不可解释路径。缓解：hooks 仅复用 `apiGet` 同源 GET；静态与组件测试禁止 orchestration/POST/provider imports。
- 阻断条件：若 Phase 41 的实际 verification 未提供 stable topic ID、server-owned freshness、snapshot binding 和 safe read endpoint，本计划必须在执行时停止为 GSD checkpoint，而不是以客户端猜测补齐。
</threat_model>
